# Судейство и журнал изменений

Учёт судейства доступен владельцу и подтверждённому главному судье соответствующего старта. Общая роль «Судья» и роль «Организатор» не дают доступа к закрытому учёту. Главный судья получает ввод результатов только своих стартов; владелец видит все.

ФИО судьи выбирается из подтверждённой команды старта или вводится вручную. Назначение хранится отдельно от результата и не влияет на место атлета. Один результат «атлет/команда + комплекс» считается одним заходом. Для комплекса на время берётся фактическое время не больше таймкапа; для незавершённого комплекса, повторений и веса — таймкап. При отсутствии времени оно помечается неизвестным. Это сумма нагрузки по результатам, а не табель смен или расчёт зарплаты.

Журнал доступен только владельцу. Он фиксирует новые изменения строк после установки миграции: кто, учётная запись/email, дата, действие, данные до/после. Время в интерфейсе и Excel — Иркутск. Секреты входа и сессионные токены не журналируются. Для крупных изменений контента записываются разделы и изменения статусов/названий стартов, а не копии изображений и документов.

Файлы копий версии 2 содержат `score_judges` и `audit_log`. Старые копии версии 1 остаются читаемыми. Восстановление версии 2 требует актуальной схемы и явного подтверждения, не запускается при старте сайта.

## Миграция

PipeCore migration command: `npm run migrate:operations`. Миграция идемпотентна: создаёт дополнительные таблицы, индексы и триггеры, не удаляет анкеты, результаты или заявки. Применяется средствами PipeCore к привязке базы `record`.

Регрессионные проверки: `npm test`. Дополнительно проверены на отдельном PostgreSQL права ролей/стартов, запись судьи без регистрации, подтверждение правки анкеты, атрибуция журнала и восстановление копии с журналом. В браузере проверены поля, фильтр, XLSX, переход к родителю и подтверждение сохранения.
